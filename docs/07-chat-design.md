# 07. チャットの設計（単発から会話へ）

いまは1問1答で、会話は「直近3往復・5分」という暫定の持ち方をしている
（`ws/session.ts` の `HISTORY_TURNS` / `HISTORY_TTL_MS`）。
保存もしていないので、あとから読み返せない。

これを **チャット（会話の単位）** として扱えるようにする。

---

## 1. 終了判定 ★ 最初に決めること

### 「終了」には2つの意味がある

混ぜて考えると決まらない。分ける。

| | 何を指すか | 効いてくるもの |
|---|---|---|
| **A. 受付の終了** | マイクをウェイクワード待ちに戻す | 体験。「また名前を呼ばないといけないのか」 |
| **B. 文脈の終了** | 次の質問に前の話を持ち越さない | 課金・回答の精度・家族間のプライバシー |

**A と B を一致させる**のが一番分かりやすい。
「追い質問の窓が閉じたらチャットも終わる」。利用者から見ると
**「名前を呼んだら仕切り直し、そうでなければ続き」**という1つの規則で済む。

### 提案する規則

```
ウェイクワード          → いまのチャットを閉じ、新しいチャットを始める
回答の読み上げが終わる  → 追い質問の窓を開く（既定 8 秒）
窓の間に話しかける      → 同じチャットの続き。窓を開き直す
窓が無言で閉じる        → チャット終了。保存して閉じる
```

### 窓を閉じる条件

| 条件 | 既定 | 理由 |
|---|---|---|
| **無言が続いた** | **8 秒** | Alexa の Follow-Up Mode が約5秒、Google の継続会話が約8秒。この辺りが相場 |
| **終了語が聞こえた** | 「ありがとう」「おわり」「もういい」「またね」 | 自然に終われる。ウェイクワードと同じ仕組み（文字列一致）で作れる |
| **往復の上限** | 10 往復 | 安全弁。長い文脈は課金が増え、回答の精度も落ちる |
| **経過時間の上限** | 5 分 | 同上。家族共用なので、前の人の話が残り続けるのも避けたい |
| **エラーが起きた** | — | 失敗したまま続きを聞かれても噛み合わない |

### 窓を開けている間の危険

**窓の間は、部屋の話し声を拾って AI に投げてしまう。** これは課金に直結する。
対策を最初から入れておく。

- **窓が開いていることを画面に出す**（「続けてどうぞ」）。黙って聞かない
- **短すぎる発話は捨てる**（1〜2文字の相槌など）
- **窓の長さを `/admin` で変えられるようにする。0 秒＝毎回ウェイクワードが要る**
  を選べるようにしておく。誤爆が気になる家庭はこれで止められる
- 読み上げ中は窓を開かない（既に決めてある）

### 採らなかった案

| 案 | 理由 |
|---|---|
| AI に「会話は終わったか」を判定させる | 呼び出しが1回増え、遅くなり、外れる。判定に課金するのは筋が悪い |
| 話題の変化で切る | 予測できない。利用者が規則を覚えられない |
| 終了ボタンだけ | 声で使う機械なのに、終わるのに手が要るのは倒錯している |
| 窓を長くして常時受付 | 部屋の会話を拾い続ける。課金とプライバシーの両方で悪い |

## 2. データの持ち方

### チャット1つ

```jsonc
{
  "id": "2026-08-27T02-15-33-a1b2",
  "startedAt": "2026-08-27T02:15:33.000Z",
  "updatedAt": "2026-08-27T02:16:40.000Z",
  "origin": "device",          // device | web
  "title": "明日の天気は",       // 最初の質問から切り出す（AI は使わない）
  "endedBy": "timeout",        // timeout | phrase | wake | limit | error | manual
  "turns": [
    { "role": "user", "content": "明日の天気は", "at": "..." },
    { "role": "assistant", "content": "…", "at": "...", "sources": [...] }
  ]
}
```

**題名は最初の質問の冒頭を切り出す。** AI に付けさせると1回ぶん課金が増え、
遅くなる。読み返すのに困らない程度で足りる。

### どこに置くか

`data/chats/<id>.json`。**1チャット1ファイル。**

- 1ファイルにまとめると、書き込みのたびに全体を読み書きすることになる
- 一覧は `data/chats/index.json` に持つ（id・題名・更新時刻・往復数・origin）。
  ディレクトリを毎回舐めるより速く、壊れても本体から作り直せる

**保存の是非**: いままで何も保存していなかった。読み返せるようにする以上、
**部屋で話した内容が Mac のディスクに残る。** そのうえで、

- 保存するのは**書き起こしと回答だけ**。**音声は保存しない**
- **保存件数に上限**を設ける（既定 200 件）。古いものから消す
- Web UI から**1件ずつ消せる**ようにする
- `data/` は `.gitignore` 済み。ファイルの権限は 0600

### 家族で共有するか

**共有する。** デバイスで聞いたことも Web UI から見える。
家族用の1台なので、別々に分ける意味が薄い。
「さっき子どもが何を聞いたか」が見えるのは、むしろ望ましい。

## 3. API

| メソッド | パス | 中身 |
|---|---|---|
| `GET` | `/api/chats` | 一覧（id・題名・更新時刻・往復数・origin）。新しい順 |
| `GET` | `/api/chats/:id` | 1件の全文 |
| `POST` | `/api/chats` | 新規チャットを作り、id を返す |
| `DELETE` | `/api/chats/:id` | 消す |
| `POST` | `/api/chat` | **`chatId` を受けるようにする。** 無ければ新規に作る |

`/api/chat` は互換を保つ。`chatId` が無ければ「1回きりのチャット」として
新規に作って返す。既存の呼び出しが壊れない。

## 4. Web UI

```
┌──────────────┬────────────────────────────┐
│ ＋ 新しいチャット │  09:54                      │
│                │                            │
│ 明日の天気は     │  「明日の天気は」              │
│ 晩ごはんの相談   │  明日の東京は晴れ時々…         │
│ 駅までの行き方   │                            │
│  …            │  ┌──────────────────────┐ │
│                │  │ 話す / やめる          │ │
└──────────────┴────────────────────────────┘
```

- **左に履歴、右に本文。** 履歴は畳めるようにする（据え置きの画面では邪魔）
- **「＋ 新しいチャット」** で仕切り直し
- 過去のチャットを開いたら**続きを話せる**（読むだけにしない）
- 1件ずつ**消せる**

### デバイスの画面はどうするか

**履歴は出さない。** デバイスは話すための機械で、読み返すのは Web UI の役割。
画面が小さく、操作もしづらい。

ただし**いまのチャットの往復は出す**（前の質問と回答が見えたほうが会話として自然）。

---

## 5. デバイスの挙動

```
待機 ──ウェイクワード──▶ 新規チャット作成 ──▶ 聞き取り ──▶ 回答
                                                      │
                          ┌───────────────────────────┘
                          ▼
                    追い質問の窓（8秒）
                      │        │
              話しかけた    無言／終了語／上限
                      │        │
                      ▼        ▼
                   同じチャット  チャット終了 → 待機
```

**画面に出す状態が1つ増える**: `following`（追い質問の窓が開いている）。
「続けてどうぞ」と出す。黙って聞いている状態を作らない。

---

## 6. 設定（`/admin`）

| 項目 | 既定 | 備考 |
|---|---|---|
| 追い質問の窓 | 8 秒 | **0 なら毎回ウェイクワードが要る** |
| 終了語 | ありがとう / おわり / もういい / またね | ウェイクワードと同じ仕組み |
| 往復の上限 | 10 | 安全弁 |
| チャットの時間の上限 | 5 分 | 安全弁 |
| 保存件数の上限 | 200 | 古いものから消す |

---

## 7. 実装の順番

1. **保存の仕組み**（`data/chats/`・一覧・上限・削除）
2. **API**（`/api/chats` 一式、`/api/chat` に `chatId`）
3. **Web UI**（履歴・新規チャット・削除）
4. **セッションをチャット単位に**（`ws/session.ts`。追い質問の窓と終了判定）
5. `/admin` に設定を足す

**1〜3 はデバイスと無関係に進められる。** 先に Web UI で会話として
成立させてから、デバイス側の窓を作るのが安全。

---

## 8. 決めたいこと

| | |
|---|---|
| 追い質問の窓は 8 秒でよいか | 短いと不便、長いと誤爆。実際に使って調整 |
| 終了語をどうするか | 「ありがとう」は会話の途中でも出る。誤終了が起きうる |
| 過去のチャットの続きを、**デバイスから**始められるようにするか | いまは Web UI だけの想定。要るなら仕組みが増える |
| 家族ごとに分けるか | いまは共有前提。分けるなら誰が話したかの判別が要る |
