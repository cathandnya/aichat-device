# 06. デバイス側の実装案（音声は Mac に流す）

> **Mac 側は実装済み。** WebSocket `/ws`・ウェイクワードの判定・状態機械・
> リングバッファは入っている（`server/src/ws/`, `server/src/ai/wake.ts`,
> `server/src/audio/ring.ts`）。いま端末の役をしているのはブラウザ（`device/web`）。
> **ハードは決まった: 家にある Echo Spot 初代に LineageOS を入れる。**
> 端末は **Kotlin のネイティブアプリ**（`device/android`）。**ビルドは通っている。**
> 残るのは実機での検証（[04](04-roadmap.md) の Phase E）。

## 前提

**サーバーは Mac に置いたまま。デバイスは端末に徹する。**

```
[デバイス]  マイク ──常時ストリーム──▶ [Mac]
            画面  ◀──状態─────────────  ウェイクワード判定
            スピーカー ◀──音声─────────  音声認識・Gemini・VOICEVOX
```

**デバイスに機械学習は載せない。** ウェイクワードの判定も Mac 側で行う。
これが効いて、デバイスは「マイクを送る・音を鳴らす・顔を出す」だけになる。

**文字は出さない。** 画面は 1.28 インチの丸で、32mm に回答を出しても読めない。
内容は声で聞く。サーバーは `question` / `answer` の文字も送ってくるが、
デバイスはそれを描かない（**取り決めは変えない**。ブラウザの画面は使い続ける）。

`device/web`（ブラウザの画面）はデバイスでは使わない。Mac 上の開発・検証用に残す。

## デバイスの責務は3つだけ

```
起動時: ws://<mac>:9801/ws?device=<端末 id> に繋ぐ
loop:
  マイクから 80ms 読む → WebSocket で送る
  受け取る: {状態} → 顔と色を切り替える
  受け取る: 音声 → 鳴らす。鳴っている間だけ口を動かす
```

判断も推論も一切しない。**これは `device/web` が既にやっていること**なので、
端末に載せるコードは新しく書かない。

> **端末 id を名乗ること**（[07](07-chat-design.md)）。ブラウザは
> `localStorage` に `browser-xxxx` を作って自動で名乗るので、**何もしなくてよい**。
> 家に2台目を置いたときも会話が混ざらない。
>
> 自作の端末を書く道に戻ったときは、`AICHAT_DEVICE_ID=living` のような
> 環境変数で持たせる。**Mac のサーバーの設定ではない**（別の機械の別プロセスなので
> Mac の `.env` は届かない）。使えるのは英数字とハイフンで 32 文字まで。

## 音声を常時流すことの検討

### 成立する

| | |
|---|---|
| 帯域 | **256 kbps**（16kHz mono 16bit）。LAN では無視できる |
| 遅延 | LAN で 1〜5ms。80ms フレームの判定には影響しない |
| Mac の CPU | 専用モデルなら 1〜2%。連続 ASR でも 8〜12%（実測） |

### プリロールの問題が消える ★

ブラウザ版では「声を検出したと気づいた頃には語頭が過ぎている」ため、
300ms のリングバッファを常に回していた（`audio/endpoint.ts`）。

**Mac が連続バッファを持つので、検出後に手前を遡って取れる。**
デバイス側にバッファは要らない。

### 引き換えに変わること

[01-requirements](01-requirements.md) には「ウェイクワード検出は**必ずローカル**」
と書いた。これは「クラウドに出さない」という意図で、**家の外に出ない点は
変わらない**（Mac は同じ家の中）。

ただし **部屋の音が常時 LAN を流れる**。次を設計として決めておく。

| | |
|---|---|
| 経路の保護 | **平文で流さない。** TLS か共有鍵。WiFi に入れた人に聞かれる |
| Mac 側 | **音声をディスクに書かない。** 判定に使ったら捨てる |
| 無音時 | デバイス側に音量のしきい値を置き、**静かなときは送らない**。数行で済む |

## ウェイクワードをどう作るか

### 案 A: 連続 ASR + 文字列一致（**実測で成立を確認した**）

音声が Mac にあるなら、専用モデルを作らずに済む。
**Apple の音声認識（ohr）を短い窓で回し続け、書き起こしに「ねえアイチャット」が
出たら起動する。**

実測（2秒窓）:

```
1回の書き起こし  0.121秒
毎秒1回で CPU 1コアの 12%（1.5秒に1回なら 8%）
```

| 利点 | |
|---|---|
| **学習が要らない** | 一番重い作業がまるごと消える |
| **語をすぐ変えられる** | 設定の文字列を書き換えるだけ。再学習も再配布も無い |
| 精度 | 本物の ASR なので、少ない学習データのモデルより素直 |

| 欠点 | |
|---|---|
| CPU | 専用モデルの 5〜10 倍（それでも Mac なら余裕） |
| 副作用 | **部屋の会話が全部書き起こされる**（Mac 内に留まるが、事実として書いておく） |
| 誤起動 | 語が日常会話に出ると起きる。→ **実測した。下記** |

### 実測（VOICEVOX の合成音声・2秒窓を1秒ずつずらす）

**結論: 「ずんだもん」で 検出 10/10・誤起動 0/15。学習なしで成立する。**

#### 1. ウェイクワードは「綴り」ではなく「認識器が出す文字列」で決める

候補を投げて、実際に何と書き起こされるかを調べた（話者3種）。

| 候補 | 一致 | 聞こえ方 |
|---|---|---|
| ねえアイチャット | **0/3** | **恋愛チャット** |
| ねえアシスタント | 0/3 | ネイ / レイ / 名アシスタント |
| ねえロボット | 0/3 | ネイロボット / 霊ロボット |
| ねえずんだもん | 0/3 | ネズンだもん / レズンだもん |
| アイチャット | 3/3 | アイチャット |
| ハローアイチャット | 3/3 | ハロアイチャット |
| オッケーコンピューター | 3/3 | オッケコンピュタ |
| ずんだもん | 2/3 | すんだもん / ずんだもん |

**「ねえ」で始まる語は全滅。** 辞書に無い並びを実在語に寄せてしまう
（ねえアイ → 恋愛）。話者や速度を変えても一貫して同じ誤りになる。

**長音（ー）は落ちる**が一貫しているので、正規化で吸収できる。

#### 2. 「ずんだもん」の評価

危険なのは **「〜んだもん」が日常の語尾**であること。そこを狙った例を混ぜた。

| 判定語 | 検出 | 誤起動 |
|---|---|---|
| `ずんだもん` のみ | 9/10 | **0/15** |
| `ずんだもん` + `すんだもん` | **10/10** | **0/15** |

外れた1件は濁点が落ちた「すんだもん」。**許容パターンに足しても誤起動は増えなかった。**

無視できた例（すべて正しく無視）:
「だって疲れてるんだもん」「行きたくないんだもん」「もう全部済んだもん」
「前はそこに住んだもんね」「ずっと待ってるんだもん」「ずんずん進んでいく」
「ずんだ餅が食べたい」

参考: **「アイチャット」は 検出 7/10・誤起動 0/15** で、「ずんだもん」に劣った。

#### 3. 費用

1窓あたり **0.14〜0.15 秒**。1秒ごとに投げて CPU 1コアの 12〜15%。

#### 4. 実マイクで測るには

ブラウザに試験専用の画面がある。

```
https://<host>:9800/wake.html
```

**AI を呼ばない。** `/ws?mode=wake` に繋ぐと、サーバーは判定だけを行い
チャットを作らず読み上げもしない（`server/src/ws/wake-probe.ts`）。
音声認識は手元なので、**何時間流しても費用はゼロ**。

- マイクはトグルで開閉する（履歴を読むだけのときに開かない）
- 窓ごとの**聞こえ方が全部出る**。当たらなかった窓も出るので、語を選び直す材料になる
- **判定語をその場で差し替えられる。** 設定（`/admin`）は書き換えないので、
  同じ部屋の音に対して「ずんだもん」と「アイチャット」を比べられる
- 起動回数・経過時間・1時間あたりの換算が出る。ログを保存できる

> **Firefox では使えない。** `AudioContext({sampleRate:16000})` を無視するため。
> 本番の経路は WAV ヘッダに実測値を書いて逃げているが、こちらは生の PCM を
> 流すので誤魔化せない。画面に警告を出して繋がない。

#### 5. この結果の限界

**合成音声での計測。** 実際の発話・小声・早口・離れた位置・生活音の中では
悪化する。とくに誤起動 0 は楽観しすぎない方がよい。**実機で測り直すこと。**

#### 6. 設計として決めること

- **判定語は複数持てるようにする**（`ずんだもん` / `すんだもん`）。
  認識器の癖を後から足せる形にしておく
- **正規化してから比較する**（空白・句読点・長音・全半角を落とす）。
  SpeechAnalyzer は語の区切りに空白を入れ、長音を落とす
- **語は設定として持つ**（`/admin` から変えられるように）。
  学習が要らない利点は「すぐ変えられる」ことなので、そこを殺さない

### 案 B: 専用モデル（openWakeWord / microWakeWord）

案 A の CPU や誤起動が問題になったときの移行先。

**日本語の既製モデルは無い。** VOICEVOX で数千件合成して学習させる
（43話者・127スタイルあるので声の多様性は稼げる）。学習は Mac か Colab で行い、
デバイスには置かない — **Mac 側で動かすので、成果物の配置も差し替えも簡単。**

案 A で動かしておけば、移行しても**デバイス側の実装は一切変わらない。**

## ハードウェア — **決定: Echo Spot 初代（2017）に LineageOS を入れる**

**自作をやめた。** 家にある Echo Spot 初代の中身を入れ替えて使う。

デバイスに機械学習が載らず、文字も出さないと決めた時点で、要求は
「丸い画面・マイク・スピーカー・WiFi・常時給電」だけになっていた。
**Echo Spot 初代はそれを全部持っていて、すでに箱に入っている。**

| | |
|---|---|
| 機種 | **Echo Spot 第1世代（2017）** |
| コード名 / 型番 | `rook` / VN94DQ |
| SoC | MediaTek MT8163 |
| 画面 | **2.5インチ・480×480 の丸** |
| 入れるもの | LineageOS 18.1（Android 11、非公式） |
| 前提 | FireOS が `5.5.6.9` / `5.5.5.2` / `5.5.3.4` のいずれか |
| 費用 | **0円**（手持ち。中古でも数千円） |

### 何が消えたか

| 前の案 | どうなったか |
|---|---|
| Raspberry Pi Zero 2 W（2,500円） | **要らない** |
| 1.28インチ丸型 SPI 液晶（3,000円） | **要らない。** Spot の画面は 480×480 で、画素数が4倍 |
| USB 会議用スピーカーフォン（5,000円） | **要らない。** マイクもスピーカーも内蔵 |
| USB 変換・microSD・電源（1,900円） | **要らない** |
| 3Dプリントのケース | **要らない。** すでに箱に入っている |
| **Python 150行のクライアント** | **要らない。** ブラウザで `device/web` をそのまま開く |
| 顔の素材の作り直し（240×240） | 480×480 向けに作る。**画素は増えたので楽になった** |

**約13,000円と、ケースの設計と、クライアントの実装が丸ごと消えた。**

### なぜこれで足りるのか

前の案を組み立てていたのは、**据え置きの丸い画面付きスピーカーが売っていない**
と思っていたからだった。実際には**Echo Spot がまさにそれ**で、
中身が Android である以上、`device/web` を開くだけで済む。

| 要件 | どう満たすか |
|---|---|
| 常時マイク | `AudioRecord` が**素で 16kHz mono 16bit** を録る |
| 読み上げ | WebSocket で届く WAV を `AudioTrack` で鳴らす |
| **エコーキャンセル** | **`AcousticEchoCanceler` を明示的に付けられる。** 自作案では USB 機器の AEC が効くかどうか、買うまで分からなかった |
| 顔と口パク | ブラウザ版（`08b750a`）と同じ作りを Kotlin に移した |
| 待機時の時計 | ROM の **AOD（常時表示）** が既定で入っている |
| 画面の明るさ | **照度センサと LiveDisplay が動く**（[05](05-issues.md) の E-2 がハード側で解ける） |
| 常時給電 | 元から据え置きの機械 |

### 引き換えに引き受けること

| | |
|---|---|
| **非公式 ROM** | Android 11 で止まっている。更新は来ない。作者も「実験的」と明記 |
| **永久文鎮化** | 多くの個体は BROM USBDL が使えない。**ブートローダ・LK・Preloader・TZ は絶対に触らない**（[09](09-echo-spot-jailbreak.md)） |
| **WPA3 非対応** | チップセットの制限。**家の WiFi が WPA3 専用だと繋がらない** |
| **ミュートスイッチが動かない** | しかも MUTE ボタンが電源ボタンを兼ねる |
| **SELinux が Permissive** | 作者が「機微なデータを置くな」と明記。音声は Mac に流すだけで端末に残らないが、**信頼された端末として扱わない**前提で設計する |
| **マイクの素性** | 既知の不具合には入っていないが、初期のビルドはサンプルレートの不具合があった。**実機で最初に確かめる** |
| **丸い画面のレイアウト** | 480×480 の丸。四隅が使えないので、中心からの距離で置く（`FaceView`）。**数値は実機で詰める** |

> **Spot 2024（第2世代）は非対応。** 別のハードで、MediaTek の穴が無い。
> こちらは Alexa のまま残す。**実験台は初代の1台だけ**にする。

### 画面（480×480 の丸）

ブラウザ版のチャット画面は横長を前提にしている（時計が左上、履歴が右上、
マイクが下中央、立ち絵が右下）。丸だと**四隅が切れる**ので、
実機の画面は作り直した。

**アプリ側は 1 枚の `View` に全部描く**（`FaceView`）。部品を並べるより、
中心からの距離で置くほうが丸い画面では素直になる。

```
     ┌───────────┐
    ╱   09:54     ╲        時計は上、小さく
   │               │
   │     (顔)      │       顔を中央に大きく
   │               │
    ╲ 聞いています ╱        状態は下
     └───────────┘
```

**文字は出さない。** 2.5インチに回答を出しても、離れたら読めない。
内容は声で聞く。

## 先に直すこと: 音声を小さく刻んで送る ★

**いまサーバーは1文ぶんの WAV を WebSocket の1メッセージで送っている。**
実測（VOICEVOX・速さ130%）:

| | 音声 | 1メッセージ |
|---|---|---|
| 「はい？」 | 0.6秒 | 28 KB |
| 普通の1文（20字） | 2.7秒 | **127 KB** |
| やや長い1文（42字） | 6.5秒 | **305 KB** |
| 長い1文（74字） | 10.5秒 | **494 KB** |

ブラウザなら受け取れるので**動かないわけではない**。それでも直す価値がある。

- **鳴り始めが速くなる。** 全部届くのを待たずに再生を始められる
- デバイスのメモリ使用量が**一定**になる（数KBのリングバッファで足りる）
- WAV ヘッダの解析が要らなくなる
- 将来もっと非力な端末に移す道が残る

20〜40ms ごとの生 PCM（16bit・VOICEVOX の 24kHz のまま）を流す形にする。
**ハードが届く前に着手できる**（ブラウザ側も同じ経路なので、そこで確かめられる）。

## ソフトウェア — **ネイティブの Android アプリ**（`device/android`）

**ブラウザで `device/web` を開く案から替えた。** 素の Android なら
それでも動くが、ネイティブにすると3つ消える。

| | ブラウザ | ネイティブ |
|---|---|---|
| **secure context** | `getUserMedia` に HTTPS が要る。自己署名を通すか Chrome のフラグを立てる | **無関係** |
| **キオスク化** | Fully Kiosk 等で全画面・自動起動・スリープ抑止を設定 | `FLAG_KEEP_SCREEN_ON` と `BOOT_COMPLETED` |
| **エコーキャンセル** | ブラウザ任せ | **`AcousticEchoCanceler` を明示的に付けられる** |
| 16kHz | `AudioContext` に変換させる | `AudioRecord` が素で 16kHz |
| ブラウザを入れる手間 | Play ストアが無いので APK を sideload | 要らない |

**secure context とキオスク化が消えるのが大きい。** 家族が何年も使う機械で、
証明書や Chrome のフラグに依存させたくない。

引き換えに**クライアントが2つになる**（`device/web` は手元で内容を読む画面として
残る）。このセッションで消してきたのが二重実装なので、そこは自覚しておく。
ただし**判断はサーバーが持っている**ので、両方に入るのは配管だけで、
取り決め（`ws/protocol.ts`）が同じである限りずれようがない。

| 層 | 何を使うか |
|---|---|
| OS | **LineageOS 18.1**（Android 11、非公式ビルド `rook`） |
| 言語 | Kotlin。`minSdk 30`（＝ Android 11） |
| 依存 | **OkHttp だけ。** androidx も Compose も入れない |
| 画面 | `View` 1枚に描く（`FaceView`）。丸い画面で四隅が使えないので、部品を並べるより中心から置くほうが素直 |
| マイク | `AudioRecord`（`VOICE_COMMUNICATION`）+ `AcousticEchoCanceler` |
| 読み上げ | `AudioTrack`。**鳴り終わるまで待つ**（書き終えた時点ではまだ鳴っている） |
| 立ち絵 | **焼き込まない。** `getExternalFilesDir` から読む。`adb push` で入れ替えられる |
| 常駐 | `BOOT_COMPLETED` で立ち上げ、`FLAG_KEEP_SCREEN_ON` で寝かせない |

構成と建て方は [`device/android/README.md`](../device/android/README.md)。

## エコーキャンセル

**Android の AEC が使える。** `getUserMedia({ echoCancellation: true })` を
指定すれば、プラットフォームのエコーキャンセルが自分の読み上げを引いてくれる。

対策の順は変わらないが、**1 の中身が「賭け」から「標準機能」になった。**

1. **ブラウザの `echoCancellation`** ← **本命**。効けば読み上げ中も判定を続けられ、
   **声で割り込める**（[05](05-issues.md) の A-3 / D-1）
2. **読み上げ中はウェイクワードの判定を止める**（Mac 側で数行）。**実装済み**
   （`ws/session.ts`）。1 が効かなくても成立する退路
3. スピーカーを離す・音量を下げる

**いまは 2 で動いている。** 1 が実機で効いたら、判定を止めるのをやめて割り込みを入れる。

> **効くのは「ブラウザ自身が鳴らした音」に対してだけ。** だから読み上げは
> 必ずブラウザ内で鳴らす（[03](03-tech-stack.md)）。いまの実装はそうなっている。
>
> 自作案（Pi + USB 会議用スピーカーフォン）では、機器のハードウェア AEC が
> 効くかどうかが買うまで分からなかった。**そこが確実になったのが、
> Echo Spot にした利点のひとつ。**

## Mac 側に要る変更

| 変更 | 中身 |
|---|---|
| **WebSocket の口** | 音声を受け、状態・文字・音声を返す。`/ws` |
| **ウェイクワードの判定** | 連続 ASR + 文字列一致。読み上げ中は止める |
| **連続バッファ** | 直近数秒を保持。検出時に手前を遡る |
| 状態機械をサーバーへ | いま `web/src/main.ts` にある 6 状態を移す。**済み**（`ws/session.ts`） |
| `HOST` を LAN に開く | デバイスから届くように |
| **`/api/*` に認証** | 開く以上、無認証では課金を他人に使われる |
| **スリープさせない** | `caffeinate -dims`。寝るとデバイスが死ぬ |

HTTPS は要らなくなる（デバイスは `getUserMedia` を使わないので
secure context の制約が消える）。ただし**音声を流す経路は保護すること。**

## いまの実装から移すもの

**移し終わった**（`device/android`）。判断はサーバーにあるので、
移したのは配管だけ。

| いまの実装 | どうなるか |
|---|---|
| `web/src/main.ts` の状態機械 | **サーバーへ移した**（`ws/session.ts`）。**済み** |
| `web/src/speech/sentences.ts` / `speaker.ts` | **サーバーへ移した**。ブラウザ側は削除済み |
| `web/src/audio/*` | Kotlin に移した（`MicStream` / `AudioPlayer`）。**素のほうが短い** |
| `web/src/character/mouth.ts` | Kotlin に移した（`Face`）。並びと間隔はそのまま |
| `web/src/styles.css` | 移さない。実機の画面は `FaceView` に描く |
| 立ち絵の素材 | 丸に収まるものを用意する。**480×480 なので余裕がある** |

## 進め方

**部品を待つ工程が消えたので、いつでも始められる。**

1. ~~WebSocket の口と状態機械を Mac 側に作る~~ **済み**（`ws/session.ts`）
2. ~~ブラウザからウェイクワードを試せるようにする~~ **済み**
3. **実マイクで誤起動と検出率を測る**。`/wake.html` を開いて放置するだけ
4. **音声を小さく刻んで送るようにする**（上記）
5. **Spot 初代を LineageOS にする** → **[09](09-echo-spot-jailbreak.md) に手順**
   - 先に **WiFi を切る**（更新されると条件から外れる）
   - 背面の隠しパネルを剥がして micro-USB を出す
   - `amonet-rook-v2.0.0` で解除 → TWRP → LineageOS 18.1（`rook`）
   - **母艦は Windows か Linux。** macOS は手順に書かれていない
6. **ROM 単体でマイクが録れることを確かめる** ← **ここが関門。**
   録音アプリで録るだけ。**ここが駄目なら計画ごと止まる**
7. **APK を入れて、繋がる・録れる・鳴ることを確かめる**
   （`device/android`。ビルドは通っている）
8. **AEC が効くか測る。** `adb logcat -s aichat` に「エコーキャンセル: true/false」が出る
9. 顔の素材を丸向けに作り、`adb push` で入れる
10. ホームアプリとして既定にする（`BOOT_COMPLETED` と `CATEGORY_HOME` は入れてある）

**3・4 と 9 の素材作りはデバイスを触る前にできる。** 5〜8 は順に潰す。
**6 で止まったら自作案（Pi）に戻る**ので、[02](02-device-selection.md) の
検討はそのまま残してある。

## 未確定・測るべきこと

ハードが手元にあるので、**測るのを待つ理由が無い。**

| | |
|---|---|
| **ROM でマイクが録れるか** ★ | **最初に潰す。** 駄目なら計画ごと止まる |
| **`AcousticEchoCanceler` が有効になるか** ★ | `adb logcat -s aichat` で見る。true なら読み上げ中の割り込みに進める |
| **エコーキャンセル** | Android の AEC がどこまで効くか。効けば読み上げ中の割り込みが入る |
| **誤起動の頻度** | 日常会話・テレビの音でどれだけ起きるか。`/wake.html` で測れる |
| **検出率** | 小声・早口・離れた位置。Spot のマイクでどこまで持つか |
| 丸い画面の見え方 | 480×480 に顔・時計・状態が収まるか |
| アプリの安定性 | 何日も動かしっぱなしで落ちないか。WiFi が切れて戻るか（繋ぎ直しは実装済み） |
| スリープ | `FLAG_KEEP_SCREEN_ON` で画面が消えないか |
| 丸い画面の実測 | `FaceView` の配置が 480×480 に収まるか。数値は実機で詰める |
| WiFi の安定性 | 切れたときの再接続 |
| 連続 ASR の CPU（Mac 側） | 12% が長時間持続するか、熱でどうなるか |
| ストリームの保護 | TLS か共有鍵か。いまは平文 |
| Mac が寝る問題 | `caffeinate` で足りるか |
