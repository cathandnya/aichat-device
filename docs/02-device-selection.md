# 02. デバイス選定

> **この章の結論（Pi 5 + Touch Display 2）は不採用。決定は
> [06](06-device-implementation.md) の「Raspberry Pi Zero 2 W + HDMI 液晶」。**
> 音声をサーバーへ常時流す形にした結果、**端末に機械学習が載らなくなった**ため、
> 要求が大きく下がった。候補は Pi Zero 2 W / ESP32-S3 / Pi 4 に移り、
> 比較は [06](06-device-implementation.md) にある。
> **サーバーは Mac に据え置く**（[04](04-roadmap.md) の「変更の記録」）。
>
> 以下は当時の比較として残す。**B の ESP32 の評価は一度逆転し、
> 最終的にはまた見送った**（安いが実装量が5倍） —
> 「画面が小さく母艦が要る」ことが欠点ではなくなった。

## 候補

| | A. Raspberry Pi 5 + 公式タッチディスプレイ | B. ESP32-S3-BOX-3 | C. iPad（既存アプリを拡張） | D. Android タブレット |
|---|---|---|---|---|
| 概算費用 | 約 3 万 | 約 1 万 | 手持ちがあれば 0 | 2〜3 万 |
| 画面 | ○ 7 インチ 720×1280 タッチ | △ 2.4 インチ（長文に不向き） | ◎ | ○ |
| マイク | ○ 好きなものを選べる | ○ デュアルマイク | ○ 内蔵（遠距離は弱い） | △ 内蔵 |
| ウェイクワード | ◎ 常時待ち受けできる | ◎ NPU で microWakeWord | ✕ iOS の制約で実質不可 | △ |
| キオスク運用 | ◎ 起動時に自動 | ◎ | ○ Guided Access | ○ |
| カメラ | ○ Camera Module 3 | ✕ | ◎ | ○ |
| 実装の自由度 | ◎ | ✕ Home Assistant 前提 | △ Xcode / TestFlight の重さ | ○ |

## 評価

**A. Raspberry Pi 5** — ウェイクワード常駐・マイク選択の自由・キオスク運用・カメラと、要件を全部満たせる唯一の候補。
弱点はソフトを全部自分で組むこと。→ **本命**。

**B. ESP32-S3-BOX-3** — Home Assistant の音声サテライトとしては定番だが（[HA 公式](https://www.home-assistant.io/voice_control/s3_box_voice_assistant/)）、
2.4 インチでは長文の回答を表示できず、STT/TTS/LLM 連携は母艦側で行う構成になる。
「Echo Show」ではなく「Echo Dot」になる。→ 見送り。将来 別室のサテライトとして足す余地はある。

**C. iPad** — 当初は「手持ちの iOS アプリに音声モードを足して先に体験を確かめる」案だった。**不採用**。
理由は3つ。(i) 常時待ち受けが iOS の制約でできず、Echo Show 的な体験の核が欠ける。
(ii) Xcode でのビルドと TestFlight 配布という重さが、体験を何度も作り直す段階と噛み合わない。
(iii) 検証で書いた Swift が Pi 版に1行も流用できない。
→ 代わりに **Mac のブラウザでローカル Web UI を動かして先に確かめる**（[03](03-tech-stack.md)）。
こちらなら書いたものがそのまま Pi で動く。

**D. Android タブレット** — ブラウザの常時録音とスリープ制御が不安定で、キオスク化の手間は Pi と大差ない。→ 見送り。

## 推奨

> **この推奨は古い。決定は「作らない」。**
> **家にある Echo Spot 初代（2017・`rook`・VN94DQ）に LineageOS を入れる**
> （[06](06-device-implementation.md)）。
>
> 要求が下がり続けた結果、こうなった。
>
> 1. **推論をデバイスに載せない**と決めた → Pi 5 の性能も 7 インチも要らない
> 2. **文字を出さない**と決めた → 画面は顔が映れば足りる
> 3. 残った要求は「丸い画面・マイク・スピーカー・WiFi・常時給電」だけ
> 4. **それを全部持った箱が家にあった**
>
> 自作案（Pi Zero 2 W + 1.28インチ丸型 SPI 液晶 + USB 会議用スピーカーフォン、
> 約13,000円）は、**Spot でマイクが動かなかったときの退路**として
> [06](06-device-implementation.md) に残してある。
>
> 以下は当時の検討として残す。

**Raspberry Pi 5（8GB）+ Raspberry Pi Touch Display 2（7 インチ）**

| 部品 | 選定 | 理由 |
|---|---|---|
| SBC | Raspberry Pi 5 8GB | VOICEVOX をローカルで動かす余地を残すため 8GB |
| 画面 | Raspberry Pi Touch Display 2（7", 720×1280, 静電タッチ） | 公式なので OS 側の対応が安定。DSI 接続で USB を塞がない |
| マイク | USB 会議マイク（Anker PowerConf 等）または Seeed ReSpeaker 2-Mics Pi HAT | 下の注記を参照。**→ 会議用に決まった**（[06](06-device-implementation.md)） |
| スピーカー | USB 会議マイク内蔵、または小型アンプ内蔵スピーカー | 会議マイクならマイク・スピーカーがひとまとめ |
| カメラ | Camera Module 3（任意） | 画像ブロックをそのまま送れる |
| ストレージ | microSD 32GB | 読み書きは少ない |
| 電源 | 公式 27W USB-C | Pi 5 + ディスプレイ + USB 機器で 5V/3A 超えを避ける |
| ケース | 3D プリント or 市販スタンド | 角度は Echo Show 同様やや上向き |

## マイクについての注記

Echo 系との体験差が一番出るところ。内蔵マイク 1 本では 1m 以上離れると日本語の認識率が落ちる。

**ただし、エコーキャンセル（自分の読み上げを拾わない）はブラウザ側でも効く。**
`getUserMedia` の `echoCancellation: true` が使えるので、当初考えていたほど
マイク本体の AEC に頼らなくてよい。ただしこれが効くのは
**「ブラウザ自身が鳴らした音」に対してだけ**なので、読み上げは必ず
ブラウザ内で再生する（[03](03-tech-stack.md) の読み上げの節）。

そのうえで、遠距離の聞き取りとノイズ抑制は依然としてハード側の差が出る。
まず手持ちの USB 会議マイクで試し、足りなければマイクアレイを検討する。
