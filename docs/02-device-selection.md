# 02. デバイス選定

## 決定 — 作らない

**家にある Echo Spot 初代（2017・`rook`・VN94DQ）に LineageOS を入れる**
（[06](06-device-implementation.md)、手順は [09](09-echo-spot-jailbreak.md)）。

要求が下がり続けた結果、こうなった。

1. **推論をデバイスに載せない**と決めた → 端末に性能が要らなくなった
2. **文字を出さない**と決めた → 画面は顔が映れば足りる
3. 残った要求は「丸い画面・マイク・スピーカー・WiFi・常時給電」だけ
4. **それを全部持った箱が家にあった**

**サーバーは Mac に据え置く**（[04](04-roadmap.md) の「変更の記録」）。
端末は音を送って音と絵を出すだけなので、自作する理由が無くなった。

## 見送った候補

| | 理由 |
|---|---|
| **ESP32-S3-BOX-3** | 2.4 インチでは長文を出せず、STT/TTS/LLM は母艦側になる。「Echo Show」ではなく「Echo Dot」になる。将来 別室のサテライトとして足す余地はある |
| **iPad**（既存の iOS アプリを拡張） | 常時待ち受けが iOS の制約でできず、体験の核が欠ける。Xcode / TestFlight の重さも、体験を何度も作り直す段階と噛み合わない |
| **Android タブレット** | ブラウザの常時録音とスリープ制御が不安定。キオスク化の手間も掛かる |

先に体験を確かめる場所は **Mac のブラウザ**にした（[03](03-tech-stack.md)）。
書いたものが実機でもそのまま動く。

## マイクについての注記

Echo 系との体験差が一番出るところ。内蔵マイク 1 本では 1m 以上離れると
日本語の認識率が落ちる。

**ただし、エコーキャンセル（自分の読み上げを拾わない）はブラウザ側でも効く。**
`getUserMedia` の `echoCancellation: true` が使えるので、当初考えていたほど
マイク本体の AEC に頼らなくてよい。ただしこれが効くのは
**「ブラウザ自身が鳴らした音」に対してだけ**なので、読み上げは必ず
ブラウザ内で再生する（[03](03-tech-stack.md) の読み上げの節）。

実機（Echo Spot）では事情が違い、**線形の引き算では消せなかった**。
最終的に帯域ごとに抑える形にしている（[06](06-device-implementation.md)）。
