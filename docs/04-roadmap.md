## 未決事項

| 項目 | 選択肢 | 決め方 |
|---|---|---|
| ウェイクワードの語 | いまは「ずんだもん」/「すんだもん」 | 合成音声では成立した。**実マイクで測り直して決める** |
| 遠距離の聞き取り | ReSpeaker の2マイクで 2〜3m 届くか | 実機で測る。足りなければマイクを変える |
| VOICEVOX の声 | 話者 ID | Phase A で家族に聞き比べてもらう |
| エコーキャンセル | ReSpeaker に AEC は無い | 読み上げ中は判定を止めて回避中。割り込みが欲しくなったらソフト AEC |
| ストリームの保護 | TLS か共有鍵か | LAN に開く前に決める |
| 追い質問の窓 | いまは 8 秒 | 短いと不便、長いと部屋の話し声を拾う。使って調整 |
| 思考レベル | いま「低」。モデルによって使える段が違う | 応答の速さと質を見て調整 |
| 感情タグが安定するか | クラウド AI に本文と一緒に吐かせる | [08](08-emotion.md)。**剥がす側は課金ゼロで固められる**が、付き方は実測しないと分からない |
| 声色まで変えるか | 表情だけ / 声色も | 同上。「別人になった」感が出ないか聞いて決める |
| 無音検出 | RMS のまま / Silero VAD | 実際の部屋で外れるようなら差し替え |
| 遠隔からの設定変更 | SSH ポート転送のまま / 他の手段 | 面倒なようなら考え直す |

## 変更の記録

- **iPad で先に検証する案は不採用**（[02](02-device-selection.md) の C）。
  常時待ち受けが iOS の制約でできず、書いた Swift が流用できないため。
  代わりに Mac のブラウザで確かめる形にした。**結果としてこの判断が効いた** —
  サーバーを Mac に据え置くと決めたいま、そのとき書いたものはほぼ本番のまま残っている。
- **「Mac で確かめて Pi 5 に移す」構成をやめた**（[06](06-device-implementation.md)）。
  音声を常時サーバーへ流す形にした結果、**ウェイクワードの判定もサーバーでできる**
  ことが分かり、端末に機械学習を載せる理由が消えた。そこで
  **サーバーは Mac に据え置き、端末は「マイクを送る・音を鳴らす・文字を描く」だけ**にする。
  - 得た: macOS の音声認識（0.14秒・誤り0件）が**本番でもそのまま使える**。
    whisper への切り替え、VOICEVOX の実時間比、メモリ — [05](05-issues.md) の C 章の
    リスクが**まとめて消えた**。端末は安く小さくできる（Pi Zero 2 W / ESP32-S3）
  - 失った: Mac を常時起動させておく必要がある。**部屋の音が常時 LAN を流れる**ので、
    経路の保護と `/api/*` の認証が要る（それまでは `HOST` を開かない）
  - 伴って **Pi 5 + Touch Display 2 は不採用**（[02](02-device-selection.md)）。
    推論が載らないので、あの性能も画面の大きさも要らなくなった
- **Cloudflare Worker を廃止し、すべてローカルサーバーに寄せた。**
  Worker の存在理由は「ブラウザに鍵を置けないから中継が要る」だったが、
  ローカルサーバー自身が鍵を持てるので二重に置く必要が無かった。
  代償（家に置く箱に課金キーが載る／`/admin` に外から入れない）は、
  上限付きキー・OS の鍵束・SSH ポート転送で受け止める。
