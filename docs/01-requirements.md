# 01. 要件と前提

## ゴール

家のテーブルに置いて、話しかけると Claude / Gemini が答え、画面に会話と補足情報が出るデバイス。
利用者は家族（`../aichat` の AIChat アプリと同じ）。

## `../aichat` から引き継いだこと

バックエンドは `../aichat/worker` を土台にしている。Cloudflare Worker として
書かれていたものを、ローカルサーバー（`device/server`）に移した。

| 項目 | 現状 | デバイス側への影響 |
|---|---|---|
| 回答 | Claude / Gemini の SSE を共通形式（`delta` / `sources` / `done` / `error`）に正規化 | 逐次表示と先読み読み上げが素直に書ける |
| 音声認識 | 音声のバイト列を受け `{"text":"..."}` を返す。16kHz mono WAV 想定・上限 1,000,000 バイト（約31秒） | ブラウザは **16kHz mono 16bit の WAV** を作る。録音は 20 秒で打ち切る |
| 設定 | モデル・システムプロンプト・回答の長さ・音声認識モデル | 画面下の「いま Haiku 4.5」の表示に使う |
| 鍵 | **ローカルサーバーだけが持つ。** `.env` か OS の鍵束から読む | ブラウザには渡らない |
| 認証 | `/api/*` には無い（127.0.0.1 でしか待ち受けないため）。`/admin` はパスワード + Cookie | LAN に開くなら認証を足す必要がある |
| モデル・system prompt・回答長 | `/admin` で決める。画面からは送らない | デバイス側に設定画面は要らない |
| 会話履歴 | サーバーは持たない（毎回 `messages` を送る） | 画面側で直近数往復だけ保持する |
| 画像 | Claude 形式の `image` ブロックを受け付ける | カメラを足しても上流の扱いは変わらない |
| 端末内モデル | **無い**（本家の `automatic` / `onDevice` は削除済み） | provider は claude / gemini の二択 |

## 機能要件

### 必須（MVP）
1. 話しかけると答える。開始は画面タップ / スペースキー（ウェイクワードは後）
2. **日本語の音声認識**。家族の会話なので日本語精度を最優先
3. 回答を**画面に逐次表示**
4. **日本語の読み上げ**。1文できた時点で先に喋り始める
5. 状態を明示（待機 / 聞き取り中 / 考え中 / 回答中 / エラー）
6. 待機時は時計。常時点灯していて邪魔にならない
7. 電源を入れれば勝手に起動する（キオスク運用）

### あると良い
- ウェイクワードでの起動
- カメラで撮って質問
- 出典（`sources`）の表示
- 物理ミュートスイッチ
- 追い質問（回答後しばらくはウェイクワード無しで続けられる）

### やらない
- スマートホーム操作・音楽再生・タイマー等の Alexa 的スキル（チャット専用という AIChat の方針）
- デバイス側の設定画面（設定はサーバー側で完結させる方針）

## 非機能要件

| 項目 | 目標 |
|---|---|
| 応答遅延 | 話し終わり → 喋り始め **2 秒以内**（STT 0.5s + 初回トークン 1s + TTS 0.5s の目安） |
| 誤起動 | 1 日数回以下。テレビの音で起きないこと |
| プライバシー | 音声は必要なときだけ外に出す。ウェイクワード検出は**必ずローカル** |
| コスト | ランニングは API 課金のみ。デバイス本体は 3〜4 万円以内 |
| 運用 | SSH で更新できる。再起動で復旧する。操作は「話す」か「画面を触る」のみ |
| 検証 | **UI と音声の一周を、AI に課金せずに確かめられること**（stub モード） |
| 鍵 | 家に置く箱に長期の課金キーを置く以上、上限付きのキーを使う |
